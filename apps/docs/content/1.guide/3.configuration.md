# Configuration

All options live under the `cookieConsent` key in `nuxt.config.ts`.

## Options

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `locale` | `string` | `'en'` | Initial UI locale. Changeable at runtime via `$consent.setLocale()`. |
| `fallbackLocale` | `string` | `'en'` | Locale used when a key is missing in the active locale. |
| `colors` | `Partial<ColorOptions>` | shadcn-like defaults | CSS color values used by the built-in components. |
| `darkColors` | `Partial<ColorOptions> \| false` | shadcn-like dark defaults | Used instead of `colors` under a `.dark` ancestor — the class Nuxt's color mode (and Nuxt UI) puts on `<html>`. `false` keeps `colors` in dark mode. |
| `texts` | `Record<string, any>` | EN/DE/ES/FR built-ins | Translations, deep-merged over the defaults. |
| `linkMap` | `Record<string, string>` | `{ privacy, imprint }` | Maps `{placeholder}` link tokens used in texts to routes. |
| `categories` | `Record<string, CategoryOptions>` | `{ necessary: { readonly: true } }` | The cookie and tracking categories your site uses. |
| `cookieName` | `string` | `'cookie_consent'` | Name of the cookie that stores the decision. Renaming it makes every visitor decide once more. |
| `consentVersion` | `string` | — | The version of your cookie policy. Change it and every visitor is asked again. See [Asking again](#asking-again-consentversion-expiresindays). |
| `expiresInDays` | `number` | `365` | Days a choice is kept before the visitor is asked again. |
| `reloadOnRevoke` | `boolean` | `true` | Reload the page when a category granted on this page is withdrawn. See [Withdrawing consent](#withdrawing-consent). |
| `googleConsentMode` | `GoogleConsentModeOptions \| false` | `false` | Send Google Consent Mode v2 commands. See [Google Consent Mode](#google-consent-mode). |

### `CategoryOptions`

```ts
interface CategoryOptions {
  readonly?: boolean        // user cannot toggle (e.g. necessary)
  kind?: 'cookie' | 'tracking'  // default 'cookie' — see below
  description?: LocalizedString // shown in the modal (falls back to the i18n key)
  requiresBanner?: boolean  // category-level; overrides the per-cookie heuristic
  defaultEnabled?: boolean  // state before the visitor chooses — see below
  reloadOnRevoke?: boolean  // overrides the module-level option for this category
  cookies?: CookieDefinition[]  // listed in the modal, deleted when consent is withdrawn
}

interface CookieDefinition {
  id: string                // cookie name, e.g. '_ga'; a trailing * matches by prefix ('_ga_*')
  descriptionKey: string    // i18n key for the description
  provider: LocalizedString // e.g. 'Google LLC'
  duration: LocalizedString // e.g. '2 years', or { en: '2 years', de: '2 Jahre' }
  requiresBanner?: boolean  // defaults to true
}

// one string for every locale, or one per locale — see Internationalization
type LocalizedString = string | Record<string, string>
```

## The intelligent banner (`requiresBanner`)

The module shows the initial consent banner **only if necessary**:

- A non-essential cookie that **requires** a banner (analytics, marketing): omit `requiresBanner` or set it to `true`.
- A non-essential cookie that should **not** trigger a banner (e.g. a theme preference set on-demand): set `requiresBanner: false`, and manage it with [`useConsentCookie`](/guide/composables#useconsentcookie) so it's only written after consent.

If **all** non-essential cookies set `requiresBanner: false`, no banner appears on first visit — only the floating settings button.
See [Preferences without a banner](/guide/usage#preferences-without-a-banner-theme-language) for the theme and
language pattern: the modal asks when the visitor first uses the feature, and nothing is stored before.

## Cookies vs cookieless tracking (`kind`)

- **`kind: 'cookie'`** (default) — backed by real device storage. The modal renders the provider/duration
  **table** from `cookies[]`; the per-cookie `requiresBanner` decides the banner.
- **`kind: 'tracking'`** — something that is not a cookie, e.g. cookieless analytics (Umami, Plausible) or session
  replays. No `cookies[]`; the modal renders a labelled **toggle** with the category `description`. A tracking
  category shows the banner **only** when its category-level `requiresBanner` is `true`.

![The settings modal: two cookie categories with their name, provider and duration table, and a cookieless Usage Statistics category as a toggle only](/screenshots/modal-1440.png)

```ts
categories: {
  analytics: {
    kind: 'tracking',
    requiresBanner: false,     // opt-out: no banner, a toggle in the FAB / settings
    description: 'Cookieless usage analytics — no cookie, no device storage.',
  },
}
```

## Default state (`defaultEnabled`)

What a visitor has **before** making a choice:

| Category | Starts |
|---|---|
| `necessary` | always on |
| `kind: 'tracking'` without a banner | **on** — that is what an opt-out means: it runs until the visitor switches it off |
| everything else (cookie categories, banner-gated tracking) | off until consent |

`defaultEnabled` overrides this per category. Use `defaultEnabled: false` for an **opt-in without a banner** —
e.g. session replays or heatmaps, which capture on-screen content and need an explicit yes, but shouldn't force a
banner on every visitor:

```ts
categories: {
  replays: {
    kind: 'tracking',
    requiresBanner: false,
    defaultEnabled: false,     // off until switched on from the FAB / settings
    description: 'Records clicks and scrolling to improve the pages. Off unless you switch it on.',
  },
}
```

Gate the matching script on the state: `useNuxtApp().$consent.state.value.replays === true`.

## Asking again (`consentVersion`, `expiresInDays`)

A choice is stored with the policy version it was made under and the time it was made, in a second, strictly
necessary cookie beside the choice (`cookie_consent_meta`, after `cookieName`). The visitor starts again from the
defaults, and sees the banner again, when:

- **`consentVersion` changed** — you added a category, a vendor or a purpose to the policy: bump the version and every
  earlier choice stops counting. Setting it for the first time asks everyone once.
- **the choice is older than `expiresInDays`** (default `365`). The French CNIL, for one, recommends asking again after
  six months, so `180` is a common choice.

```ts
cookieConsent: {
  consentVersion: '2026-10',
  expiresInDays: 180,
}
```

When the choice was made is available as `$consent.consentedAt` (milliseconds, `null` before a choice).

## Google Consent Mode

`googleConsentMode` maps your categories to Google's [Consent Mode v2](https://developers.google.com/tag-platform/security/guides/consent)
types. The module then puts the `default` command in the page head, so it runs before any Google tag, and sends an
`update` with the visitor's choice on every page load and every change:

```ts
cookieConsent: {
  googleConsentMode: {
    mapping: {
      necessary: 'security_storage',
      preferences: ['functionality_storage', 'personalization_storage'],
      analytics: 'analytics_storage',
      marketing: ['ad_storage', 'ad_user_data', 'ad_personalization'],
    },
    waitForUpdate: 500, // ms the tags wait for the update (default 500)
  },
}
```

Every Consent Mode type is sent. A type is `granted` only while every category mapped to it is granted; a type that no
category maps is always `denied`. The commands go to `window.dataLayer`, which gtag.js and Google Tag Manager both read,
so load the tag itself as usual (for example with `useScript` and `$consent.triggers.analytics`, or unconditionally
when you rely on Consent Mode's cookieless pings).

## Withdrawing consent

When the visitor switches a category off, the module:

1. calls the `consent:revoked` hook, so you can stop what the category started (see [Events](/guide/usage#events));
2. deletes the category's declared `cookies` — by name, or by prefix for an `id` ending in `*`, on the site's domain
   and its parent domains. HttpOnly cookies, and cookies set on a path other than `/`, cannot be deleted from the
   browser; clear those on the server;
3. reloads the page if the category was granted at some point on the current page, because a script that already ran
   keeps running until the page is left. `reloadOnRevoke: false` turns this off for the module or for one category,
   when the `consent:revoked` hook stops everything the category started.

A [`useConsentCookie`](/guide/composables#useconsentcookie) cookie is deleted as soon as its category is withdrawn.

## Full example

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@websideproject/nuxt-cookie-consent'],

  cookieConsent: {
    locale: 'en',
    fallbackLocale: 'en',

    linkMap: {
      privacy: '/privacy-policy',
      imprint: '/imprint',
    },

    categories: {
      necessary: { readonly: true },
      preferences: {
        cookies: [
          {
            id: 'theme_preference',
            descriptionKey: 'cookies.preferences.theme.description',
            provider: 'Our Website',
            duration: '1 year',
            requiresBanner: false,
          },
        ],
      },
      analytics: {
        cookies: [
          {
            id: '_ga',
            descriptionKey: 'cookies.analytics.ga.description',
            provider: 'Google LLC',
            duration: '2 years',
          },
        ],
      },
    },

    texts: {
      en: {
        cookies: {
          preferences: {
            theme: { description: 'Saves your selected theme (dark/light).' },
          },
          analytics: {
            ga: { description: 'Used by Google Analytics to distinguish users.' },
          },
        },
      },
    },
  },
})
```

See [Internationalization](/guide/i18n) for the full text structure, and [Usage](/guide/usage) for wiring it all together.
